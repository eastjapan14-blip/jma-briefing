気象庁の発表を10分ごとに見張り、動画にする価値のある新着だけをスマホへ届ける

気象庁の防災情報XML・報道発表・公式YouTube・アメダスの記録を、GitHub Actions が10分ごとに確認します。段階を判定し、重複や続報を除き、台風のような広域の情報はまとめてから、ntfy で iPhone に通知します。Mac を起動しておく必要はありません。

10分確認の間隔
2系統防災情報と観測記録
0円無料の範囲で運用

段階ごとに届き方が違う

段階対象届き方
A記者会見（報道発表と会見動画）1件ずつすぐ
B台風、線状降水帯の半日前予測、警報級の可能性全般気象情報はすぐ。府県・地方の情報は下の規則でまとめる
C特別警報の新規発表、気象防災速報、記録的短時間大雨すぐ。同じ回に複数県なら1通
D1か月・3か月・暖候期・寒候期予報1件ずつすぐ（優先度は低め）

台風のときは、波が落ち着いてから1通にする

台風が近づくと、本庁の全般気象情報、各管区の地方気象情報、各地方気象台の府県気象情報が、約80分かけて十数件出ます。1件ずつ通知すると読めないため、次の規則で束ねます。

  • 広域とみなす条件：台風、または3時間以内に同じ事象で4つ以上の府県・地方が出たとき。
  • 送る時点：最後の追加から20分新着がないとき、または最初の保留から90分たったとき。
  • 局地的な情報：1県だけの大雨などは、府県の情報でも1件ずつすぐ届く。
  • 土砂災害警戒情報と洪水予報：補足情報が繰り返し出るので1時間ごとに1通。

同じ内容が何度も来ないようにしている

  • 「〜気象解説情報」は「〜気象情報」と同じ本文の別電文なので読まない。
  • 府県気象情報に流れる「気象防災速報」の写しは、段階Cと重なるので読まない。
  • 特別警報は電文の中身を読み、新しく「発表」されたときだけ通知する。継続中は同じ見出しが繰り返し流れる。
  • 「解除」「可能性は低くなりました」などの情報は対象外。
  • 送信済みのURLを保存し、保険として ntfy 側の直近24時間の履歴も照合する。

観測記録には珍しさを添える

record-hunter は、気象庁のCSVにある極値更新の印から記録を拾い、地点ごとの順位ページで歴代順位を確かめます。通知には珍しさを4段階で付けます。

📊 珍しさ ●●● とても珍しい
・統計51年（1976年〜）の10月で最大
・41年ぶりの更新（前回 203.0mm、1985/10/12）
・同じ日に全国でほか8地点も24時間降水量が記録級

統計10年未満の地点は記録が出やすいので常に「珍しくない」。気象庁の更新状況ページは統計10年目以降の地点しか載せないため、翌日の照合でもこれらは対象外にしている。

知っておきたい制約

  • GitHub の定期実行は混雑時に数時間遅れるため、外部の cron-job.org から10分ごとに起動している。GitHub 側の定期実行は保険として残している。
  • 台風のまとめ通知は最大で90分遅れる。動き出しの合図は、波の最初にすぐ届く全般気象情報で受け取る。
  • 観測値は速報値で、後から修正されることがある。
  • 発信は気象庁の発表の範囲に留める。観測値と発表の解説は予報にあたらないが、独自の予測は扱わない。

使っているサービス

  • GitHub Actions：公開リポジトリなので実行時間は無料。
  • ntfy.sh：無料・アカウント不要。トピック名を知っている人は誰でも購読できるので、名前は GitHub の秘密情報に置き、外に出さない。
  • cron-job.org：無料。GitHub の起動用トークンは、このリポジトリの Actions 操作だけに権限を絞っている。

この資料には、トピック名やトークンなどの秘密情報は載せていません。
